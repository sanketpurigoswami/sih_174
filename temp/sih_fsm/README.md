# SIH PS 26174 — Final Protocol FSM

This package is the deterministic protocol-validation layer that sits after your NLP procedure parser and your CV/rule-based event generator.

## Architecture

```text
NLP model
   |
   | procedure JSON
   v
+-------------------+
|   Protocol FSM    |
+-------------------+
   ^
   | semantic CV events (JSONL/JSON)
   |
YOLO + rules + tracking
```

The FSM **does not consume YOLO boxes, MediaPipe landmarks, or raw frame predictions**. It consumes semantic events such as:

```json
{"timestamp":4.60,"action":"PLACE","object":"MOUSE","target":"SLOT_1","confidence":0.98}
```

## Inputs

### 1. NLP procedure JSON

The package accepts the `task_metadata.json` generated by your existing `sih_nlp_v3` model, and also a simpler `expected_actions` format.

Example:

```json
[
  {
    "step_id": 1,
    "source_text": "Pick up the mouse and place it in Slot 1.",
    "high_level_action": "PLACE",
    "object": "MOUSE",
    "target": "SLOT_1",
    "atomic_actions": [
      {"action":"REACH","object":"MOUSE","target":"SLOT_1","order":1},
      {"action":"GRASP","object":"MOUSE","target":"SLOT_1","order":2},
      {"action":"LIFT","object":"MOUSE","target":"SLOT_1","order":3},
      {"action":"MOVE","object":"MOUSE","target":"SLOT_1","order":4},
      {"action":"PLACE","object":"MOUSE","target":"SLOT_1","order":5},
      {"action":"RELEASE","object":"MOUSE","target":"SLOT_1","order":6}
    ],
    "completion_condition": "RELEASE"
  }
]
```

The existing NLP package can therefore remain the language side. You only need to point the FSM at its exported metadata JSON.

### 2. CV observed-event JSONL

One semantic event per significant action, **not one row per video frame**.

Minimum:

```json
{"timestamp":1.20,"action":"GRASP","object":"MOUSE","target":"SLOT_1","confidence":0.94}
```

Recommended:

```json
{"timestamp":1.20,"action":"GRASP","object":"MOUSE","target":"SLOT_1","confidence":0.94,"action_confidence":0.97,"object_confidence":0.98,"target_confidence":0.99,"object_id":7,"hand":"right"}
```

Supported actions include `REACH`, `GRASP`, `PICK_UP`, `LIFT`, `MOVE`, `TRANSFER`, `PLACE`, `RELEASE`, `INSERT`, `REMOVE`, etc. Aliases such as `grab`, `pick_up`, `put`, `drop` are normalized.

## What the FSM checks

- Correct step and atomic action
- Correct object
- Correct target
- Wrong action
- Wrong object
- Wrong target
- Out-of-order future step
- Repetition of an already completed step
- Low-confidence observation (`UNCERTAIN`)
- Unknown event
- Full experiment completion
- Next required step/action after a valid event

`IDLE` can be ignored so your CV side does not need to suppress every no-action period perfectly.

## Important event-generation rule

Your CV side should debounce frame-level predictions. For example, if the hand stays near the mouse for 20 frames, do **not** send 20 `GRASP` events. Send one semantic `GRASP` event when the rule engine determines that the state transition has actually occurred.

For placement, prefer:

```text
object was manipulated
+ object enters target ROI
+ object becomes stationary for N frames
+ hand subsequently separates
=> PLACE then RELEASE
```

This avoids declaring a static object already sitting in a slot as a new placement.

## CLI

From the package root:

```bash
python -m sih_fsm.cli \
  --procedure examples/task_metadata.json \
  --observed examples/cv_observed.jsonl \
  --out output
```

Outputs:

```text
output/verification.json
output/verification.jsonl
output/verification.csv
output/summary.json
```

## Python API

```python
from sih_fsm.normalizer import load_procedure, load_observed
from sih_fsm.fsm import ProtocolFSM

steps = load_procedure("task_metadata.json")
events = load_observed("cv_observed.jsonl")
fsm = ProtocolFSM(steps, min_confidence=0.55)

for event in events:
    result = fsm.process(event)
    print(result.to_dict())
```

## Integration with your existing NLP package

You already have a working NLP module under `sih_nlp_v3`. Do not replace it.

The hand-off is:

```text
English instructions
      |
      v
sih_nlp_v3
      |
      +--> task_metadata.json
                 |
                 v
             THIS FSM
                 ^
                 |
          cv_observed.jsonl
                 ^
                 |
        YOLO + rules + tracking
```

That gives you a clean separation:

- NLP = **what should happen?**
- CV/rules = **what happened?**
- FSM = **is it correct?**
- GUI/TTS/logger = **how do we tell the operator?**

## Live mode

The same `ProtocolFSM.process(event)` method is intended for real-time use. You do not need to wait for the complete video. Your CV thread can create an `ObservedEvent`, send it to the FSM, and immediately route the returned `FSMResult` to the GUI, TTS, and logger.
